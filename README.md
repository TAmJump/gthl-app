# gthl-app — 115en. / NPO GO TO HAPPY LIFE 生活支援アプリ

終身サポート事業計画（2026.11）の「53 Webアプリ開発・公開要件」MVP範囲の実装。

| 範囲 | 内容 |
|---|---|
| 無料登録 | 会員登録・ログイン（会員ID `GTHL-000001` 形式） |
| デジタル証明書 | 本人確認・登録の事実のみを示す無料証明書。期限付き照会QR（30日）、再発行で旧証明書は失効 |
| 第三者照会 | `verify.html#<token>`。氏名・本人確認の有無・期限のみ表示 |
| 生活支援 | 21分野・240項目カタログから申込 → 職員が見積 → 本人同意 → 着手 → 完了（受付・着手・完了時刻を記録） |
| マイペット | 引取先・同意、以前のペットの遺骨・供養の希望 |
| 生前・死後の希望 | 医療・連絡・葬儀・住まいの希望（法的契約ではない旨を明示） |
| 契約の管理 | 他社を含む契約の登録と、同一業務区分の重複表示 |
| 任意寄付 | Square 決済リンク（未設定時は「準備中」表示） |
| 職員管理画面 | `staff.html`。申込の見積・着手・完了、本人確認の記録、監査ログ（管理者のみ） |

## 構成

```
docs/     画面（GitHub Pages で公開）
worker/   API（Cloudflare Worker + D1）
scripts/  動作確認用スクリプト
```

## 個人情報の扱い

- 12桁の個人番号・カード番号は保存しない
- 住所・緊急連絡先・医療の希望・相談内容・ペットの投薬などは AES-GCM で暗号化して D1 に保存（鍵は Worker シークレット `DATA_KEY`）
- パスワードは PBKDF2（10万回）でハッシュ化。セッション・照会トークンはハッシュのみ保存
- 職員の閲覧・操作は `audit_log` に記録
- 本人確認は JPKI（デジタル庁認証API）導入まで、職員の面談・書類確認を記録する方式

## ローカル開発

```bash
cd worker && npm install
echo "DATA_KEY=$(head -c32 /dev/urandom | base64)" > .dev.vars
npm run db:local
npx wrangler dev --port 8787
# 別ターミナル
cd docs && python3 -m http.server 8788   # http://localhost:8788
bash scripts/smoke.sh http://localhost:8787
```
